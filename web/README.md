# web — фронтенд «сетки»

Production-фронтенд «сетки» на реальном API. Его собирает `web/Dockerfile`,
CI проверяет тесты и PWA, а nginx проксирует `/api` на backend.

## Стек

- React 19 + TypeScript, Vite 8
- React Router 7 (history API, прямые ссылки)
- TanStack Query 5 — кэш и повторные запросы
- Zustand 5 + `persist` — группа, подгруппа, тема, избранное, недавние
- Axios — клиент BFF (`/api/v1`)
- Vanilla CSS — `src/styles/app.css` (токены и компоненты)
- Firebase Messaging — существующий воркер `public/firebase-messaging-sw.js`
- `vite-plugin-pwa` — манифест и офлайн-кэш расписания

## Структура

```text
web/
  index.html                 # тема до первой отрисовки, шрифты, иконки
  vite.config.ts             # dev-прокси /api, PWA, манифест
  public/
    firebase-messaging-sw.js # FCM-воркер из web/ (плейсхолдеры VITE_*)
    icon-*.png, favicon.*    # ассеты редизайна
  src/
    api/                     # client, типы BFF, React Query хуки
    components/              # оболочки, расписание, шторка пары
    pages/                   # today, week, search, changes, settings, entity
    lib/                     # слоты, даты, FCM, хуки
    store/preferences.ts     # persisted-настройки
    styles/app.css           # визуальная система редизайна
```

## Запуск

```bash
cd web
npm ci --legacy-peer-deps
npm run dev
```

Дев-сервер: `http://127.0.0.1:5174`. Запросы `/api/*` проксируются на
`VITE_PROXY_TARGET` (по умолчанию `http://127.0.0.1:8080` — backend из
`docker-compose`). Для мока или другого хоста:

```bash
VITE_PROXY_TARGET=http://127.0.0.1:8082 npm run dev
```

Полезные параметры только для dev:

- `?now=09:00` на `/g/:id/today` — подменить время для проверки блока «сейчас»;
- `?day=YYYY-MM-DD`, `?week_start=YYYY-MM-DD` — выбранный день/неделя;
- `?day=...` фиксирует день: без него экран «Сегодня» после 18:00 или
  после последней пары сам показывает следующий учебный день;
- `?slot=N` — открыть шторку пары (используется ссылками «Открыть пару»);
- `?q=` на `/search` — начальный запрос.

## Экран «Сегодня»

Без явного `?day` экран выбирает день автоматически:

- после 18:00 или когда все пары на сегодня уже закончились — показывается
  следующий учебный день (воскресенье пропускается, в субботу вечером —
  понедельник следующей недели);
- в воскресенье — понедельник.

Над расписанием появляется пояснение и кнопка «Показать сегодня»; после
перехода на сегодня там же есть кнопка возврата к следующему дню. Ссылка
с `?day=...` всегда открывает указанный день и не переключается сама.

## Анимации

Отдельной библиотеки анимаций нет — движение построено на CSS и нативном
View Transitions API, чтобы не тянуть в бандл framer-motion/motion:

- переходы между разделами (`<AppLink>` и программный `navigate`) оборачиваются
  в `document.startViewTransition`; контентная часть `#content` / `#d-content`
  помечена `view-transition-name: page`, поэтому верхняя панель, сайдбар и
  нижние табы остаются на месте, а содержимое плавно сменяется;
- смена дня и недели — `key` на контейнере + `rise-in` анимация;
- строки пар проявляются каскадом, баннер следующего дня выезжает сверху,
  шторка пары и её backdrop появляются с fade/slide;
- всё это отключается при `prefers-reduced-motion: reduce`, а в браузерах без
  View Transitions навигация работает как раньше, без анимации.

Если понадобится физика пружин и жесты, можно добавить `motion` (бывший
framer-motion), но для текущих сценариев хватает нативных средств.

Проверка production-сборки (манифест, precache, FCM-воркер):

```bash
npm run build
npm run test:build
```

Требуется Chromium: `playwright-core` использует системный или кэшированный
браузер из `~/.cache/ms-playwright`; путь можно задать через `CHROME_PATH`.
Порты: `E2E_APP_PORT` (15174), `E2E_MOCK_PORT` (18082).

Переменные production-сборки (те же имена, что в `web/Dockerfile`):

- `VITE_API_BASE` — база BFF, по умолчанию `/api/v1`;
- `VITE_API_ORIGIN` — база для POST/PATCH (subscribe, настройки);
- `VITE_FIREBASE_*` — конфиг FCM, включая `VITE_FIREBASE_VAPID_KEY`.

`npm run build` не запускает eslint/тесты — проверка типов входит в `tsc -b`.
CI для `web/` остаётся прежним: `npm ci --legacy-peer-deps && npm run build`
на Node 20 (тесты и e2e в CI не подключены).

## Маршруты

| Путь | Экран |
| --- | --- |
| `/` | редирект на сохранённую группу или `/search` |
| `/search` | поиск групп, преподавателей и аудиторий |
| `/g/:groupId/today` | «Сегодня» (на десктопе редирект на неделю) |
| `/g/:groupId/week` | неделя: список на мобильном, сетка + день на десктопе |
| `/g/:groupId/changes` | изменения, фильтр «моя группа / все группы» |
| `/g/:groupId/settings` | тема, подгруппа, уведомления, отписка |
| `/tutor/:id`, `/auditory/:id` | расписание преподавателя/аудитории |

## Короткие ссылки и превью

Ссылка `/g/{id}` без `today/week` работает как умная: мобильный браузер
переходит на `/today`, десктоп — на `/week`.

- В dev/SPA это делает React-маршрут `GroupLandingRoute`.
- В production nginx отдаёт `/g/{id}` из backend-эндпоинта
  `GET /api/v1/share/group/{id}`: HTML с `og:title`, `og:description`,
  `og:image` (`/og.png`, 1200×630) и клиентским редиректом.
- Так Telegram и другие link-preview-боты видят корректное название группы
  и картинку, а браузер сразу открывает нужный экран.
- `index.html` содержит общие OG/Twitter-метаданные для остальных страниц,
  а SPA обновляет `document.title` и description при навигации.

## CI и деплой

- `frontend-test` выполняет `npm ci`, `npm run build`, `npm test` и
  `npm run test:build`; `frontend-e2e` прогоняет браузерные сценарии.
- `web/Dockerfile` собирает это приложение на Node 20, подставляет Firebase в
  `dist/firebase-messaging-sw.js` и отдаёт статику через `web/nginx.conf`.
  Build-args берутся из repository secrets `VITE_FIREBASE_*`; без реальных
  значений (не `-`) push-уведомления работать не будут.
- CI деплоит образы с фиксированными именами контейнеров
  `omsu_setka_backend` / `omsu_setka_frontend`, очищает старые контейнеры и
  проверяет health перед успехом.
- `vite-plugin-pwa` генерирует `dist/sw.js`; FCM-воркер живёт отдельно и
  регистрируется Firebase при получении токена.
- Плагин несовместим с инъекциями Rolldown (Vite 8): `manifest.webmanifest`
  лежит в `public/` как статический файл, а `sw.js` регистрируется вручную в
  `src/main.tsx`. `npm run test:build` следит, чтобы манифест, precache и
  плейсхолдеры FCM-воркера не разъехались.
- ID группы в URL и API — `dict_groups.id`, а не `real_group_id`.
  `real_group_id` из справочника может указывать на другую группу и для
  расписания/подписок/изменений не используется.

## Проверка на реальном бэкенде

```bash
# .env рядом с docker-compose.yml: ADMIN_KEY, CORS_ALLOWED_ORIGINS
docker compose -f docker-compose.yml up -d --build backend
REAL_API=http://127.0.0.1:8080 npm run test:real-api
```

Скрипт поднимает Vite с прокси на реальный BFF и проверяет словари, поиск,
расписание группы по `dict_groups.id` (включая совпадение названий занятий),
преподавателя, аудиторию, `/changes`, полный цикл `subscribe → PATCH →
unsubscribe`, а затем проходит браузером поиск → группу → неделю → шторку.
Нужен доступ к upstream (`eservice.omsu.ru`) и заполненный справочник.
